# 采集与恢复

入口参数见 SKILL.md。三个来源分别为 submitted（我发起）、executed（我处理）、cc（抄送我）。默认日期 2014-01-01 至当天（Asia/Shanghai）；报告明确范围及后端可见性，不声称包含已删除或不可见审批。

输出目录包含：
- raw/lists：各日期段各页原始响应。
- raw/*-complete.json：完整角色列表。
- raw/details：每实例详情，文件名为 ID 的 SHA-256，兼容 Windows。
- approvals.json：去重数据和角色来源。
- manifest.json：身份、日期、分页记录、失败及 complete。

本机 DWS 1.0.62 曾在大页或第 11 页报内部错误，这不是永久 API 限制。程序选择每页 20 条，某段达到 10 页且还有数据时按日期二分。实测 DWS 对完全空的日期段返回 `values: []` 时可能省略 `hasMore`，程序将这种结构视为终止空页并记录推断；非空页缺失分页标记、重复页、父窗口已见 ID 未出现在子窗口、单日仍无法穷尽，均停止并保持 incomplete。未知错误不盲重试。

详情通常已包含 formValueVOS、operationRecords、tasks；缺少记录或任务时补取相应独立接口，保留补充结果。附加接口失败也必须记为不完整。

按 processInstanceId 去重保留 sourceItems。按模板代码分类，同名不同代码拆 Sheet，标题用于显示。日期范围与不带日期列表可能有服务端语义差异；用户要求所有历史时，对授权范围内来源作交叉核对，有差异就报告，不凭日期分段自行宣称所有历史。

--resume 必须使用相同 profile、日期、roles。隔天续传显式使用 manifest 的日期；默认 to 会变化。成功角色列表与成功详情复用，未完成角色从首页重新取；原始页保留核查。这是角色/实例级恢复，不承诺逐页续传。

.run-lock 防止并行混写。异常终止可能留下锁，先检查 PID 和开始时间，确认原进程已退出才删除锁；不自动删除活跃锁。更新已经完成的审批状态应创建新输出目录，而非复用旧快照。

失败保留结构化诊断。脚本不做盲重试，DWS 负责 token 刷新；若服务端明确 retryable=true，Agent 按等待字段做一次有界重试。认证/权限或未知错误不跨账号绕过。部分导出不得标 complete。
